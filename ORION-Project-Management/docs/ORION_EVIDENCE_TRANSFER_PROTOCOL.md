# ORION_NEXT — Evidence Transfer Protocol

الإصدار: 1.0
الحالة: ACTIVE / PROPOSED FOR GOVERNANCE APPROVAL
المشروع: ORION_NEXT
المستودع الرسمي: `badeemorse-gif/ORION_NEXT`

---

## 1. الغرض

هذا البروتوكول يحدد الطريقة الرسمية لنقل **الأدلة البصرية والتقارير** إلى قائد ORION_NEXT عندما تكون هذه الأدلة موجودة في مكان أو بيئة لا يستطيع القائد الوصول إليها مباشرة.

الهدف هو منع توقف سير العمل بسبب عدم قدرة القائد على الوصول المباشر إلى صورة أو تقرير أو مخرجات موجودة لدى المطور أو على جهاز آخر، مع الحفاظ على GitHub باعتباره مصدر الحقيقة للمشروع والكود.

---

## 2. نطاق الاستخدام

يُستخدم هذا البروتوكول **للصور والملفات التقريرية فقط** عندما يتعذر على القائد الوصول مباشرة إلى مصدرها.

أمثلة:

- Screenshot يحتاج القائد إلى قراءته.
- صورة لمعلومة موجودة على جهاز المطور.
- تقرير طويل لا يمكن نقله عمليًا داخل المحادثة.
- Log أو نتيجة اختبار محفوظة كملف ويحتاج القائد إلى فحصها.
- ملف Evidence مؤقت مطلوب لإثبات حالة أو نتيجة.

هذا البروتوكول لا يغيّر مصدر الحقيقة للكود أو حالة المستودع.

---

## 3. مبدأ الفصل بين Evidence وSource of Truth

### GitHub هو Source of Truth للمشروع

يبقى GitHub المرجع الرسمي لـ:

- الكود.
- Branches.
- Commits.
- Git lineage.
- Pull Requests.
- التعديلات المعتمدة.
- حالة التكامل.
- الوثائق الرسمية المخزنة في المستودع.

### مواقع رفع الصور والملفات ليست Source of Truth

أي خدمة خارجية لرفع صورة أو ملف تُستخدم فقط كوسيلة **Evidence Transfer**.

لا يجوز اعتبار رابط خارجي بديلاً عن:

- Commit.
- Branch.
- File داخل المستودع.
- GitHub PR.
- قرار معماري.

إذا كان المحتوى يجب أن يصبح جزءًا رسميًا من المشروع، فيجب Materialize/توثيقه داخل GitHub وفق الإجراء المناسب بعد مراجعته.

---

## 4. مسؤولية صاحب الدليل

عند الحاجة إلى نقل صورة أو تقرير إلى القائد:

1. يرفع صاحب الدليل الصورة أو الملف إلى وسيلة مشاركة مناسبة.
2. يرسل الرابط إلى القائد.
3. لا يعيد كتابة محتوى الصورة أو التقرير يدويًا إلا إذا طلب القائد ذلك صراحة.
4. لا يضيف تفسيرًا أو استنتاجًا نيابة عن القائد ما لم يُطلب منه ذلك.
5. يوضح فقط ما إذا كان الرابط يشير إلى الصورة/الملف المطلوب.

---

## 5. مسؤولية القائد

القائد هو المسؤول عن تفسير Evidence واتخاذ القرار الناتج عنه.

عند استلام صورة أو ملف:

- يحدد ما يجب استخراجه.
- يقرأ الدليل المتاح مباشرة عندما تكون أداة الوصول متاحة.
- يميز بين المعلومات المثبتة والاستنتاجات.
- لا يعتمد معلومة غير قابلة للإثبات من الدليل.
- لا يحول Evidence غير المؤكد إلى قرار معماري.

إذا تعذر الوصول إلى الرابط أو تعذر التحقق من المحتوى، تكون الحالة **UNVERIFIED** ولا تُعامل كحقيقة مثبتة.

---

## 6. قاعدة عدم التخمين

لا يجوز لأي وسيط أو مطور اختلاق أو استنتاج بيانات غير ظاهرة في الصورة أو غير موجودة في الملف.

عند تنفيذ مهمة استخراج بصري أو تقريري:

- `NOT_VISIBLE` = المعلومة غير ظاهرة في الدليل.
- `UNCERTAIN` = المعلومة موجودة لكن قراءتها غير مؤكدة.
- `UNVERIFIED` = تعذر الوصول إلى الدليل أو التحقق منه.

لا يجوز استبدال هذه الحالات بتخمين.

---

## 7. تقييد نطاق الاستخراج

إذا طلب القائد استخراج حقول محددة من صورة أو تقرير، يجب استخراج **الحقول المطلوبة فقط**.

ممنوع على منفذ الاستخراج:

- توسيع المهمة من تلقاء نفسه.
- اتخاذ قرار معماري.
- إعلان `APPROVED`.
- إعلان `CHANGES REQUIRED`.
- تعديل الكود.
- تعديل GitHub.
- تغيير Branch.
- إنشاء Commit إلا بتكليف مستقل وصريح.
- اقتراح حلول لم يطلبها القائد.

وظيفة ناقل Evidence هي نقل الدليل، وليست قيادة المشروع.

---

## 8. التقارير الطويلة

عندما يكون التقرير طويلًا بدرجة تجعل نقله داخل المحادثة غير عملي، يجوز تحويله إلى ملف ورفع الملف ثم إرسال الرابط للقائد.

يفضل أن يكون الملف بصيغة قابلة للقراءة النصية كلما كان ذلك ممكنًا، مثل:

- TXT.
- Markdown.
- PDF.
- DOCX.
- JSON عند الحاجة.

يجب أن يحتوي التقرير على البيانات الفعلية دون اختصار يغير معناها.

---

## 9. الصور

عندما تكون المعلومة موجودة بصريًا، يفضل نقل الصورة الأصلية أو نسخة واضحة منها بدل إعادة وصفها يدويًا.

لا يجوز ضغط الصورة أو تعديلها بطريقة قد تغير البيانات المراد إثباتها.

إذا احتوت الصورة على معلومات حساسة، يجب إزالة أو إخفاء المعلومات الحساسة قبل رفعها إلى خدمة خارجية، أو استخدام وسيلة وصول خاصة مناسبة.

---

## 10. الأمن والسرية

لا يجوز رفع البيانات السرية إلى خدمة عامة أو غير موثوقة، بما في ذلك:

- Passwords.
- API Keys.
- Access Tokens.
- Private credentials.
- أسرار المستودع.
- بيانات شخصية غير لازمة.
- أي Secret يمكن استخدامه للوصول إلى النظام.

إذا احتوى الدليل على Secret، يجب إزالته أو إخفاؤه قبل المشاركة، مع الحفاظ على الجزء الضروري لإثبات الحالة.

---

## 11. الاستمرارية عند حدود المحادثة

حدود الاستخدام في قناة المحادثة لا يجب أن تصبح نقطة توقف للمشروع.

لذلك يجب أن تكون حالة المشروع قابلة لإعادة البناء من:

1. GitHub كمصدر الحقيقة للكود والحالة الرسمية.
2. الوثائق الرسمية داخل المستودع.
3. Evidence خارجي مؤقت عند الحاجة فقط.
4. تقارير المطورين النهائية.

لا يجوز أن تكون معلومة حرجة وحيدة الوجود داخل رسالة محادثة غير موثقة إذا كان يمكن توثيقها في المستودع.

---

## 12. بروتوكول التسليم إلى القائد

عند نقل Evidence، يكون التسلسل:

```text
Source / Developer Environment
        ↓
Image or Report File
        ↓
Approved Sharing Link
        ↓
Project Leader
        ↓
Direct Evidence Review
        ↓
Decision / Verification
        ↓
GitHub Documentation when required
```

---

## 13. قاعدة القيادة

أي قائد جديد لـ ORION_NEXT يجب أن يقرأ هذا البروتوكول قبل استئناف العمل، وأن يلتزم بالفصل التالي:

> **Evidence Transfer ينقل الحالة إلى القائد؛ ولا ينقل سلطة القرار إلى ناقل Evidence.**

القائد هو من يفسر الدليل ويقرر أثره على المشروع.

---

## 14. قاعدة الاعتماد

هذا البروتوكول لا يمنح أي Evidence خارجي صفة الاعتماد تلقائيًا.

الدليل الخارجي = Evidence.

القرار الناتج عنه = قرار القائد.

الحالة الرسمية للمشروع = GitHub + الوثائق المعتمدة.

---

## 15. Definition of Done لهذا البروتوكول

يُعتبر البروتوكول مطبقًا عندما:

- يكون القائد قادرًا على طلب صورة أو تقرير محدد.
- تصل الصورة أو التقرير كرابط قابل للوصول أو كملف متاح للقائد.
- لا يعتمد القائد على إعادة وصف يدوي غير ضروري.
- لا يتخذ ناقل Evidence أي قرار نيابة عن القائد.
- لا يصبح التخزين الخارجي مصدر الحقيقة للمشروع.
- تبقى القرارات والحالة الرسمية قابلة للتتبع داخل GitHub.
