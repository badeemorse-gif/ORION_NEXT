23. قاعدة عدم الاعتماد الدائري
==================================================

يجب تجنب Circular Dependencies.

إذا ظهر اعتماد دائري بين مكونات المشروع:

يجب:

1. تحديد السبب.
2. تحديد الطبقات المتأثرة.
3. مراجعة التصميم.
4. اختيار الحل المعماري.
5. تسجيل القرار إذا كان التغيير جوهريًا.

26. Bootstrap Boundary
==================================================

Bootstrap مسؤول عن:

- الإنشاء.
- التسجيل.
- الربط.
- تجهيز الاعتماديات.

ولا يجب أن يصبح مكانًا لتنفيذ منطق التحليل أو القرار.


==================================================
27. Application Boundary
==================================================

Application مسؤولة عن تنسيق حالات الاستخدام ودورة حياة التطبيق.

لا يجب أن تحتوي على تفاصيل منخفضة المستوى تخص:

- الاتصال بمزود البيانات.
- التخزين.
- الحسابات الداخلية.
- تنفيذ التحليل المتخصص.


==================================================
28. API Boundary
==================================================

API تمثل واجهة الوصول الخارجية.

يجب أن تستدعي طبقات التطبيق والخدمات المناسبة.

لا يجب أن تنفذ منطق الأعمال الأساسي مباشرة داخل Router أو Server.


==================================================
29. GUI Boundary
==================================================

GUI تمثل واجهة المستخدم.

يجب أن تتعامل مع التطبيق من خلال طبقات واضحة.

لا يجب أن تنفذ عمليات التحليل الأساسية داخل عناصر الواجهة.


==================================================
30. Storage Boundary
==================================================

Storage مسؤول عن التخزين والاسترجاع.

لا يجب أن يحتوي على منطق القرار أو التحليل.

Repository يمثل طبقة تنظيم الوصول عندما تكون مطلوبة.


==================================================
31. Scheduler Boundary
==================================================

Scheduler مسؤول عن:

- متى يتم التشغيل.
- ما المهمة التي يتم تشغيلها.
- تنظيم التكرار.

ولا يملك منطق التحليل نفسه.


==================================================
32. Reports Boundary
==================================================

Reports مسؤول عن إخراج النتائج.

لا يجب أن تصبح التقارير مصدرًا لمنطق التحليل أو القرار.


==================================================
33. Security
==================================================

الأسرار الحساسة لا تدخل في:

- Source Code.
- Git.
- Reports العامة.
- Logs العامة.

تشمل الأسرار:

- API Keys.
- API Secrets.
- Passwords.
- Tokens.
- Private Keys.

- النتيجة.
- التحليل.
- القرار.
- التقرير الناتج.
