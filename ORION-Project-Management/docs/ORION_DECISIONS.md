5. ADR-016 — توحيد ملكية وثائق المشروع وإزالة الوثائق التشغيلية المتداخلة
==================================================

التاريخ:

2026-08-11

الحالة:

ACCEPTED

المجال:

Project Governance / Documentation

### السياق

تراكمت وثائق متعددة تؤدي وظائف متقاربة، وبعضها أصبح يعكس Baseline تاريخية بدل الحالة الحالية.

### المشكلة

وجود أكثر من مصدر لنفس نوع المعلومة يزيد احتمال:

- التكرار.
- تعارض المرحلة الحالية.
- تضارب المعمارية الحالية مع Baseline قديمة.
- تشتيت GPT والمطور بين مصادر متوازية.

### القرار

اعتماد الوثائق التالية كمصادر التشغيل الرسمية:

GPT EXECUTION RULES
CONTROL INDEX
PROJECT CHARTER
WORK PROTOCOL
ARCHITECTURE
PROJECT STATE
ROADMAP
FUTURE ROADMAP
FUTURE PRODUCT VISION
ARCHITECTURE FINDINGS
DECISIONS
CHANGELOG
KNOWN PROBLEMS

وإلغاء الوثيقتين المتداخلتين تشغيليًا:

- ORION_EXECUTION_METHOD.md
- ORION_TARGET_ARCHITECTURE_IMPLEMENTATION_BASELINE.md

تم دمج المبادئ المفيدة منهما في WORK PROTOCOL وARCHITECTURE وROADMAP.

### السبب

تقليل عدد مصادر الحقيقة دون فقدان المبادئ المهمة، مع الحفاظ على قدرة المطور على الاستمرار دون إعادة فتح المسار الحالي.

### التأثير

- PROJECT STATE يبقى مالك الحالة الحالية.
- ROADMAP يبقى مالك ترتيب التنفيذ.
- FUTURE ROADMAP يبقى مالك الأهداف المستقبلية الكبرى.
- ARCHITECTURE يبقى مالك المعمارية الحالية.
- WORK PROTOCOL يبقى مالك طريقة التنفيذ.
- CHANGELOG وDECISIONS وFINDINGS تحتفظ بالتاريخ ولا تستخدم كمصادر بديلة للحالة الحالية.

### الحالة

ACCEPTED

==================================================
8. قاعدة عدم التخمين
==================================================

عند تعارض الكود أو الاختبارات أو GitHub مع وثيقة قديمة:

1. فحص الواقع الفعلي.
2. تحديد الحقيقة الحالية.
3. تحديد المصدر غير المتوافق.
4. تحديث الوثيقة المالكة.
5. تسجيل قرار جديد فقط إذا كان التغيير معماريًا أو تشغيليًا مؤثرًا.
