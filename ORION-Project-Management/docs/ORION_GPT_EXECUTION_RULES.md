==================================================
1. الوظيفة
==================================================

هذه الوثيقة هي البوابة التشغيلية الإلزامية لـ GPT داخل ORION.

تحدد فقط قواعد تشغيل GPT، المراجعة، الوصول إلى الوثائق، GitHub، التعديل، المزامنة، والاستمرارية.

لا تخزن الحالة أو المعمارية أو خارطة الطريق بدل الوثائق المالكة لها.

==================================================
2. قاعدة الأمر 1
==================================================

إذا كان أول أمر في رسالة المستخدم هو:

1

فالمعنى الإلزامي:

نفذ الخطوة التالية من حالة ORION الحالية.

التسلسل:

1. قراءة هذه الوثيقة.
2. قراءة ORION_CONTROL_INDEX.md.
3. قراءة ORION_PROJECT_STATE.md.
4. تحديد المرحلة الحالية.
5. تحديد آخر خطوة معتمدة.
6. تحديد الخطوة التالية من ORION_ROADMAP.md.
7. مراجعة الوثائق المتخصصة المطلوبة فقط.
8. تنفيذ الخطوة التالية فقط.

==================================================
3. قاعدة ما قبل كل رد مرتبط بـ ORION
==================================================

يجب:

- الوصول إلى هذه الوثيقة وقراءتها.
- قراءة CONTROL INDEX.
- قراءة PROJECT STATE عندما تكون الحالة ذات صلة.
- عدم الاعتماد على ذاكرة المحادثة بدل الوثائق والمستودع.

==================================================
4. مستويات المراجعة
==================================================

المستوى 1 — مراجعة سريعة:
قواعد التنفيذ + Control Index + الحالة عند الحاجة + الوثيقة المباشرة.

المستوى 2 — مراجعة مستهدفة:
الوثائق المرتبطة + الكود + الاختبارات + البحث عن معلومة مؤثرة عند الحاجة.

المستوى 3 — مراجعة موسعة:
تستخدم عند تعارض، قرار معماري كبير، تغيير بنية، مراجعة شاملة، أو عدم إمكانية تحديد الحقيقة الحالية.

لا تتم قراءة كل الوثائق في كل رسالة بلا سبب.

==================================================
5. عدم تجاهل الوثائق
==================================================

عدم قراءة وثيقة في رسالة معينة لا يعني تجاهلها.

إذا ظهرت معلومة مهمة في وثيقة غير مالكة:

1. يتم التحقق منها.
2. يعتمد أثرها أثناء القرار إذا كانت صحيحة.
3. تحدد الوثيقة المالكة.
4. تنقل أو توثق في المكان الصحيح عند تنظيف الوثائق.

15. Findings
==================================================

Finding جديدة لا تعني إيقاف التطوير تلقائيًا.

توقف فقط إذا أصبح الاستمرار سيكسر Contract أو يثبت تعارضًا معماريًا أو يبني على قرار غير محسوم أو يضر الهدف الرئيسي.

إذا تم تنفيذ Finding ونجح Verification:

VERIFIED / CLOSED

ولا تحذف من التاريخ.
