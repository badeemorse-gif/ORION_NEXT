==================================================
1. الوظيفة
==================================================

هذه الوثيقة هي البوابة التشغيلية الإلزامية لـ GPT داخل ORION.

تحدد قواعد تشغيل GPT، المراجعة، الوصول إلى الوثائق، GitHub، التعديل، المزامنة، الاستمرارية، ونظام التطوير بالحزم الكاملة.

لا تخزن الحالة أو المعمارية أو خارطة الطريق بدل الوثائق المالكة لها.

==================================================

==================================================

إذا كان أول أمر في رسالة المستخدم هو:

1

نفذ الخطوة التالية من حالة ORION الحالية.

التسلسل:

1. قراءة هذه الوثيقة.
2. قراءة ORION_CONTROL_INDEX.md.

7. مراجعة الوثائق المتخصصة المطلوبة فقط.
8. تنفيذ الخطوة التالية فقط.

4. مستويات المراجعة
==================================================

المستوى 1 — مراجعة سريعة:
قواعد التنفيذ + Control Index + الحالة عند الحاجة + الوثيقة المباشرة.

المستوى 2 — مراجعة مستهدفة:
الوثائق المرتبطة + الكود + الاختبارات + البحث عن معلومة مؤثرة عند الحاجة.

المستوى 3 — مراجعة موسعة:
تستخدم عند تعارض، قرار معماري كبير، تغيير بنية، مراجعة شاملة، أو عدم إمكانية تحديد الحقيقة الحالية.

لا تتم قراءة كل الوثائق في كل رسالة بلا سبب.

==================================================
5. عدم تجاهل الوثائق
==================================================

عدم قراءة وثيقة في رسالة معينة لا يعني تجاهلها.

إذا ظهرت معلومة مهمة في وثيقة غير مالكة:

1. يتم التحقق منها.
2. يعتمد أثرها أثناء القرار إذا كانت صحيحة.
3. تحدد الوثيقة المالكة.
4. تنقل أو توثق في المكان الصحيح عند تنظيف الوثائق.

==================================================
12. التطوير بالحزم الكاملة
==================================================

نموذج التطوير الافتراضي للمطورين هو:

ARCHITECTURE BOUNDARY
↓
COMPLETE VERTICAL / FUNCTIONAL SLICE
↓
CONTRACTS
↓
IMPLEMENTATION
↓
INTEGRATION COMPATIBILITY REVIEW
↓
DOCUMENTATION
↓
COMMIT TO DEVELOPER BRANCH
↓
FINAL REPORT

لا يطلب من المطور إرسال رسالة تقدم بعد كل ملف أو تعديل صغير.

إذا كانت المهمة محددة بوضوح:

- ينفذها كاملة حتى Definition of Done.
- لا يسأل هل يكمل، ما دام داخل نطاقه.
- لا يرسل تحديثات مرحلية إلا عند Architectural Blocker حقيقي.
- عند اكتمال الحزمة يرسل تقريرًا نهائيًا واحدًا.

الهدف هو منع فقدان السياق بين عشرات الرسائل الصغيرة وتقليل التضارب بين المطورين.

==================================================
13. الاختبار والمزامنة المحلية أثناء التطوير
==================================================

لا تتم مزامنة كل تعديل صغير إلى Local فقط من أجل تشغيل اختبار.

Contract Tests تُكتب مع الكود عند الحاجة، ويمكن استخدام GitHub/CI عندما تكون متاحة.

الاختبارات المحلية الثقيلة وFull Verification تُؤجل إلى Integration Gate أو عندما تكون مطلوبة لاتخاذ قرار.

لا يعتبر المطور نفسه قد أجرى اختبارًا محليًا إلا إذا كان لديه وصول وتنفيذ فعلي لذلك الاختبار.

==================================================
14. Final Materialization
==================================================

عند اكتمال الحزم المطلوبة وقرار التكامل:

GITHUB COMMITS / INTEGRATED STATE
↓
CLEAN FINAL MATERIALIZATION
↓
LOCAL ORION_NEXT
↓
FULL VERIFICATION / E2E / PARITY

المزامنة النهائية يجب أن تكون من نسخة نظيفة ومحددة بالـbranch والـcommit، وليس من Working Tree قديم أو Snapshot غير Git.

لا يجوز أن تكتب عملية Final Materialization فوق Working Tree تطويري غير مقصود دون بوابة واضحة.
