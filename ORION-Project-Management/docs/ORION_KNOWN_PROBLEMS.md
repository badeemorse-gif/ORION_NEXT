# ORION — سجل المشاكل المعروفة

الإصدار: 1.0
الحالة: تأسيسي
المشروع: ORION
المستودع البرمجي: binansScanner
مستودع إدارة المشروع: ORION-Project-Management


==================================================
1. الغرض
==================================================

هذا الملف هو السجل الرسمي للمشاكل المعروفة في مشروع ORION.

يتم استخدامه لتسجيل:

- الأخطاء البرمجية.
- المشاكل المعمارية.
- مشاكل الاعتماديات.
- مشاكل الاختبارات.
- مشاكل التشغيل.
- مشاكل التكامل.
- مشاكل الأداء عند إثباتها.
- مشاكل الأمان عند اكتشافها.
- أي سلوك غير متوافق مع التصميم المعتمد.


==================================================
2. الهدف
==================================================

الهدف من هذا السجل هو منع:

- نسيان المشاكل المكتشفة.
- إعادة التحقيق في نفس المشكلة دون معرفة تاريخها.
- اعتبار المشكلة المعروفة مشكلة جديدة.
- إغلاق مشكلة دون توثيق سبب إغلاقها.


==================================================
3. قاعدة أساسية
==================================================

لا يتم تسجيل شيء كمشكلة مؤكدة اعتمادًا على التخمين.

يجب التمييز بين:

- مشكلة مؤكدة.
- اشتباه يحتاج إلى تحقيق.
- تحسين مقترح.
- قرار معماري.

إذا كان الأمر قرارًا معماريًا، يتم تسجيله أيضًا في:

ORION_DECISIONS.md


==================================================
4. حالات المشاكل
==================================================

OPEN

المشكلة مؤكدة ولم تتم معالجتها.

INVESTIGATING

يتم التحقيق في سبب المشكلة.

FIXED

تم تنفيذ إصلاح للمشكلة.

VERIFIED

تم اختبار الإصلاح والتأكد من نجاحه.

CLOSED

تم إغلاق المشكلة رسميًا.

WONTFIX

تم اتخاذ قرار بعدم إصلاحها، مع توثيق السبب.

DUPLICATE

المشكلة مكررة لمشكلة أخرى.


==================================================
5. مستويات الأولوية
==================================================

CRITICAL

تمنع تشغيل النظام أو تسبب خطرًا كبيرًا على البيانات أو الأمان.

HIGH

تؤثر بصورة كبيرة على وظيفة أساسية.

MEDIUM

تؤثر على وظيفة أو مكون ولكن النظام يستطيع الاستمرار.

LOW

مشكلة محدودة التأثير.

==================================================

لا توجد حاليًا مشاكل مؤكدة مسجلة في هذا السجل.

يجب عدم إضافة مشكلة إلى هذه القائمة إلا بعد إثباتها أو توثيقها كحالة تحتاج إلى تحقيق.


==================================================
8. المشاكل المكتشفة أثناء المراجعة
==================================================

سيتم إضافة المشاكل هنا بالتسلسل:

KP-001
KP-002
KP-003
...


==================================================
9. قاعدة التحقيق
==================================================

عند اكتشاف مشكلة:

1. تسجيل المشكلة.
2. تحديد نطاقها.
3. تحديد الملفات المتأثرة.
4. تحديد السبب الجذري.
5. تحديد الحل.
6. تنفيذ الحل.
7. اختبار الحل.
8. مراجعة التعديل.
9. تحديث حالة المشكلة.
10. تحديث CHANGELOG عند الحاجة.


==================================================
10. العلاقة مع CHANGELOG
==================================================

ليس كل خطأ يتم اكتشافه يحتاج بالضرورة إلى إدخال تفصيلي في CHANGELOG.

لكن عندما يتم إصلاح مشكلة مؤثرة، يجب تسجيل التغيير في:

ORION_CHANGELOG.md

بحيث يكون هناك:

Known Problem
↓
Fix
↓
Verification
↓
Changelog


==================================================
11. العلاقة مع القرارات المعمارية
==================================================

إذا كشفت المشكلة عن خلل في التصميم أو الحاجة إلى تغيير معماري:

1. تسجل المشكلة هنا.
2. يتم تحليلها.
3. يتم اتخاذ القرار المعماري.
4. يسجل القرار في ORION_DECISIONS.md.
5. يتم تنفيذ القرار.
6. يتم تحديث المشكلة.


==================================================
12. قاعدة عدم الإغلاق المبكر
==================================================

لا تعتبر المشكلة محلولة لمجرد أن:

- الكود تغير.
- الخطأ لم يظهر مرة واحدة.
- البرنامج بدأ التشغيل.

يجب التحقق من الإصلاح وفق طبيعة المشكلة.

الحالة المفضلة:

FIXED
↓
VERIFIED
↓
CLOSED


==================================================
13. المشاكل المتعلقة بالملفات
==================================================

إذا كانت المشكلة مرتبطة بملف معين، يجب ذكر:

- اسم الملف.
- المكون.
- الطبقة.
- سبب المشكلة.
- الملفات المتأثرة.

ولا يتم إصلاح الملف بصورة معزولة إذا كان التعديل يؤثر على ملفات أخرى.


==================================================
14. المشاكل المتعلقة بالاعتماديات
==================================================

إذا اكتشفت مشكلة في Dependency:

يجب فحص:

- مصدر الاعتماد.
- المستهلك.
- دورة الاعتماد.
- Dependency Container.
- Bootstrap.
- الاختبارات المتأثرة.

ولا يتم إزالة الاعتماد أو تغييره دون تقييم تأثيره.


==================================================
15. المشاكل المتعلقة بالاختبارات
==================================================

إذا فشل اختبار:

لا يتم تعديل الاختبار لمجرد جعله ينجح.

يجب أولًا تحديد:

هل المشكلة في:

- الكود؟
- الاختبار؟
- العقد المعماري؟
- البيانات؟
- البيئة؟

ثم اتخاذ القرار المناسب.


==================================================
16. المشاكل الأمنية
==================================================

أي مشكلة تتعلق بـ:

- API Key.
- API Secret.
- Password.
- Token.
- Private Key.
- بيانات اعتماد.
- تسريب معلومات حساسة.

تعتبر مشكلة أمنية ويجب التعامل معها بأولوية مناسبة.

لا يتم تسجيل الأسرار نفسها داخل هذا الملف.


==================================================
17. المشاكل التي تحتاج قرارًا
==================================================

إذا ظهرت مشكلة لا يمكن حلها دون تغيير معماري، يتم وضعها في حالة:

INVESTIGATING

حتى يتم اتخاذ القرار المناسب.

بعد القرار:

- تحديث هذه الوثيقة.
- تحديث ORION_DECISIONS.md.
- تنفيذ التغيير.
- اختبار النتيجة.
